2. Before you leave internet — MUST DO

A. MATLAB uses ONLINE licensing. It needs internet to start. On a TP-Link with no internet, MATLAB may refuse to open. Fix: give the laptop internet and the TP-Link at the same time (section 3, option 1: phone USB tethering). Also: start MATLAB while online and do not close it.
B. PX4 firmware toolchain is NOT set up yet. Without it, Step 1 (flash the Pixhawk) fails with PX4BaseDirNotFound. The setup downloads PX4 from GitHub, so do it with internet:
  1. Restart PC once if not done since WSL install.
  2. MATLAB → Home → Add-Ons → Manage Add-Ons → UAV Toolbox Support Package for PX4 Autopilots → ⚙ → Setup.
  3. Choose WSL / Ubuntu-22.04, board Pixhawk 6C. Run the commands the screen gives you in the Ubuntu window (exactly as shown, they pin the right PX4 version).
  4. Let it build (10–30 min). Check after: codertarget.pixhawk.internal.getPX4BaseDir() prints a folder.
Do NOT reinstall/update the PX4 package or Raspberry Pi Blockset afterwards — that wipes the MathWorks patches.

3. Network: laptop ↔ drone

Option 1 (recommended): TP-Link Wi-Fi + phone USB tethering

  1. Plug phone by USB → phone settings → turn on USB tethering. Laptop now has internet over USB (MATLAB licence + Claude keep working).
  2. Laptop Wi-Fi → join the TP-Link network, password 16142992. Windows may say "No internet" — fine.
  3. Check: open cmd → ipconfig. The Wi-Fi adapter must show 192.168.0.x.
  4. Check the Pi: ping 192.168.0.204 → replies = good.
  5. If web pages stop working: Windows is using the TP-Link for internet. Open PowerShell as admin: 
    Get-NetIPInterface -AddressFamily IPv4 | Sort InterfaceMetric | ft ifIndex,InterfaceAlias,InterfaceMetric
Set-NetIPInterface -InterfaceAlias "Wi-Fi" -InterfaceMetric 50
    (Lower number = preferred for internet. The 192.168.0.x drone traffic still goes over Wi-Fi.)

Option 2: TP-Link only (no internet)

Works only if MATLAB was started while online and stays open. Claude is not reachable.

Pi IP changed / unknown? Find it

  • Browser → http://192.168.0.1 (or http://tplinkwifi.net) → TP-Link admin → DHCP → Client List → look for rpib.
  • cmd: ping rpib or ping rpib.local → shows the IP.
  • cmd: arp -a → list of 192.168.0.x devices.
  • Then in MATLAB: set_drone_ip('NEW.IP.HERE')

SSH into the Pi (check it is alive)

ssh rpi@192.168.0.204        (password: rpib)
ls /dev/ttyACM*              (Pixhawk on USB → shows /dev/ttyACM0)
df -h                        (free space)
exit

6. Flight checklist

  1. Pixhawk calibrated (accel, compass, RC) in QGroundControl. MAV_SYS_ID = 1.
  2. Ground telemetry radio NETID = 21 (else you may talk to another team's drone).
  3. Arena: red 0.1 m line, even lighting, fans/AC off near arena (sim fails in strong draft).
  4. First: props on, kill switch in hand, short hover only. Then the simple default-style track.
  5. Expected behaviour (from sim): flies 1.0 m high, follows line, centres on circle, descends 0.2 m/s, disarms at 0.1 m. If line lost: searches 25 s then lands where it is.

7. Moving the Pi to the laptop hotspot (optional, risky)

Possible, but only do it if the TP-Link route fails. If the Pi cannot find the hotspot, it is unreachable until you edit the SD card. Keep the TP-Link profile so the Pi falls back to it.

  1. Laptop: Settings → Network → Mobile hotspot → band 2.4 GHz (Pi Zero has no 5 GHz) → set name e.g. ENTITY_HS and a password → turn On.
  2. While still on the TP-Link: ssh rpi@192.168.0.204, then: 
    # Raspberry Pi OS Bookworm (NetworkManager):
sudo nmcli dev wifi connect "ENTITY_HS" password "YOUR_HS_PASSWORD"
#   -> SSH drops; the Pi moves to the hotspot. TP-Link profile is kept.

# Older OS (Bullseye, no nmcli): add a block, then reboot
sudo nano /etc/wpa_supplicant/wpa_supplicant.conf
network={
    ssid="ENTITY_HS"
    psk="YOUR_HS_PASSWORD"
    priority=10
}
sudo reboot
  3. Find the new IP: laptop Settings → Mobile hotspot → Connected devices (shows rpib + IP, usually 192.168.137.x), or cmd arp -a.
  4. MATLAB: set_drone_ip('192.168.137.x')
  5. To go back: turn the hotspot off → Pi reconnects to the TP-Link → set_drone_ip('192.168.0.204').

Note: Windows hotspot normally needs an internet source to share (e.g. phone USB tethering). Option 1 in section 3 gives the same result with less risk.
